## Implementation Strategy

### MVP — Phase 1 + 2 + US1

The smallest honest increment is the band mounted, the sections gone, the ground re-anchored, and the
three headings arriving in word units. **Read the caveat before shipping it**: under FR-016 the
replacement has already happened at T012, so an "US1-only" landing is not a safe half-state — it is the
deletion plus arrival, with a static composition where the assembly should be. That is a valid,
content-complete, shorter page (and blueprint §4's own fallback is the static locked composition), but
it must be described as such and not as a paused feature.

### Full delivery, in order

1. Phase 1 baselines (nothing else can be proven afterwards).
2. Phase 2 structure — stop at the T013 checkpoint if the shell will not pin at 360.
3. Phase 4 choreography (driver) in parallel with Phase 3 arrival (qoder).
4. Phase 5 immovable-layer proofs before any visual tuning is signed off — it has veto power.
5. Phase 6, including T049's baseline refresh, without which the drift guard is reading a stale DOM.

### Where this feature is likely to fail, stated up front

- **The length criterion.** The band is taller than 2,961px before any of that height is reclaimed by
  the pin, so SC-001 is arithmetic that has not been done yet (T027, T011).
- **The pin at 360.** A sticky shell taller than the viewport never pins, and the composition at 360 is
  taller than one viewport (T013). If that fails, US2's mechanism fails — not partially.
- **Arrival inside a pinned shell.** The IO-based arming logic and a sticky transform stage have
  conflicting ideas about what "in view" means (T020).
- **Two states, one sticky box.** The blueprint's pinned beats and its flowing locked composition are
  not the same geometry (T011).
- **A guard that agrees with its own author.** T016 exists because this exact failure already happened
  once in this checkout — the story is in the `UNANCHORED_SECTIONS` doc comment of
  `lib/atmosphere/progression.ts`, next to the line that records it.
