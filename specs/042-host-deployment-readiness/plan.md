## Summary

This feature prepares Hami Hamrah for reliable, progressive deployment onto a Linux host server (VPS or dedicated instance) without downtime or data risk. It establishes:
1. **Lightweight Standalone Production Build**: Enables Next.js `output: "standalone"` to bundle an isolated runner with a 60–80% reduced footprint.
2. **Deep Health & Readiness Observability**: Replaces legacy mock `/api/health` with a comprehensive probe that reports uptime, memory, version, and live PostgreSQL latency with fail-fast HTTP 503 handling for upstream reverse proxies.
3. **Environment Hygiene & Fail-Fast Validation**: Centralizes environment contracts, documents `.env.example`, and ensures secure cookie and header forwarding behind TLS reverse proxies.
4. **Host Preflight & Safe Migration Tooling**: Creates an automated pre-deployment validator (`tools/deploy/preflight.mjs`), PM2/systemd templates, and a step-by-step phased quickstart runbook enforcing Constitution database rules (never allow `prisma migrate reset`).

## Technical Context

- **Language/Version**: TypeScript 5.x, Node.js >= 20.x, React 19 / Next.js 16 (App Router).
- **Primary Dependencies**: Next.js (`next`), Prisma ORM (`@prisma/client`), PostgreSQL (`pg`).
- **Storage**: PostgreSQL database, managed via Prisma schema (`prisma/schema.prisma`).
- **Testing**: Vitest test suite (`tests/unit/host-deployment-health.test.ts`), preflight verification suite (`tools/deploy/preflight.mjs`), `tsc --noEmit`.
- **Target Platform**: Linux host server (Ubuntu/Debian) running Node.js 20+ LTS behind reverse proxy (Nginx/Caddy) with process management (PM2/systemd).
- **Project Type**: Full-stack Next.js web application with database persistence.
- **Performance Goals**: Standalone deployment package under 150MB, health check response < 150ms, preflight audit < 5s, zero downtime cutover.
- **Constraints**: Never run destructive database resets (`prisma migrate reset`), maintain clean architectural seams, fail fast on missing environment variables.
- **Scale/Scope**: Host deployment configuration, health API, environment validation, build tooling, and runbook.
